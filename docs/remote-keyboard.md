# 电视键盘与遥控中心

## 用户交互

主遥控页只提供屏幕和鼠标分页。右下角悬浮键盘打开电视键盘弹框；遥控中心入口打开通用电视遥控器弹框。旧的 gestures/buttons 偏好设置会过滤迁移，保留 screen/mouse 的既有顺序。

遥控中心集中五向/OK、返回、主页、菜单、音量、静音、电源、信号源、频道、搜索和播放。使用标准 Android TV keycode；信号源、频道和播放的效果取决于电视及当前应用。方向键点按一次、长按连续加速；音量键点按一次、长按后由原触点上下滑动调节，松手收起临时滑轨；频道键点按一次、长按打开原生数字键盘，松手后键盘保留。音量滑轨读取电视 `media volume --stream 3 --get` 报告的真实范围，设备不支持回读时显示错误，不虚构百分比；频道数字通过逐位按键及确认发送，电视未提供通用的当前频道回读，不能据此声称已切台。帮助说明通过弹框显示，主页面不展示教学提示。

鼠标的可见性说明放在使用提醒弹框；坐标触控模式可在提醒中开启/关闭点击位置提示。点击位置提示不会伪装成真正的常驻系统鼠标。

## 双向文本同步

打开时先读取电视当前具有输入焦点、可编辑的控件及全文。手机新增、删除、清空或修改后串行写入电视；空闲时约每 200ms 读取一次电视更新。网络和控件响应会增加同步时间，不承诺零延迟。

确定按钮先提交手机输入法的组词结果，等待最新文本被电视确认，再执行编辑器确认动作；Android 11+ 优先 ACTION_IME_ENTER，不支持时使用配对的 Enter 按下/抬起。关闭保留已同步修改，不是撤销。

RemoteKeyboardSync 在一个循环中合并待写文本，并保证确认发生在最新写入之后。UITextView 不发布 markedText，避免把中文组词过程中的拼音当最终文本发送；电视刷新也不覆盖正在进行的组词。

## 电视端与协议

TextSync.java 通过 app_process 以已授权的 ADB shell 身份连接 UiAutomation；无需安装 APK 或输入法。连接指定 DONT_SUPPRESS_ACCESSIBILITY_SERVICES，避免停止已有无障碍服务；仅在键盘弹框打开期间保持会话。

GET 返回当前输入框 token 及 UTF-8/Base64 文本。SET 同时带上 token、预期原文和目标全文，只有当前焦点和原文均匹配才执行 ACTION_SET_TEXT，并再次读回确认。空字符串使用单独的 `-` 标记，单个字段最多 8192 UTF-8 字节。CONFIRM 同样检查 token 和文本。

焦点或电视文本并发变化时返回冲突，保留手机草稿并停止写入；用户明确点击从电视重新同步后才重新加载。密码框、不支持设置文本的控件、超长输入和不可用的自动化连接显示不支持/失败。不会自动改用退格或追加命令覆盖未知内容。

Shell 成功或流写入成功不等于同步成功，必须收到与请求序号对应的状态回执。读响应有大小上限和 5 秒超时；取消弹框关闭流，电视进程退出并断开自动化连接。输入原文不写入日志。

旧 sendRemoteText / input text API 仍保留用于兼容其他调用，ASCII 编码规则不变；新键盘 UI 不使用该追加路径。

## 构建与测试

构建助手：设置 JAVA_HOME、ANDROID_JAR、R8_JAR 后运行 scripts/build-android-text-sync.sh，生成 Resources/TVADBTextSync.dex。

- tests/run-sync-preview-tests.sh：读取初始电视内容、UTF-8 协议、清空、外部更新、确认顺序、冲突保留草稿、旧分页迁移和遥控按键映射。
- tests/test_text_sync_helper.py：需 JAVA_HOME；用 Android API 替身执行生产 Java，验证中文/emoji、清空、冲突、密码排除、当前焦点及 Enter 配对。
- tests/run-directional-key-tests.sh、tests/test_remote_keys.py：长按、取消、加速及快速方向键协议。

这些主机测试及 iOS 编译不能证明索尼等 OEM 的 UiAutomation 权限、自绘/WebView 控件、中文组词或电视确认动作可用。没有连接电视或 iPhone，尚无真机双向同步结果。

## 候选词与清空断开修复

同步启动时读取所有输入法组件名，仅将包名传入助手作为排除列表。只接受 TYPE_APPLICATION 应用窗口及其所属包的编辑节点，不再使用可能指向候选栏的 getRootInActiveWindow 兜底。输入法即使错误标注成应用窗口，其包名也会被排除。

真正的应用输入框被暂时保留；输入法取走焦点时，不会把候选词当新输入框。只有同一前台应用、同一窗口及无歧义的资源 ID 才能重新定位清空后重建的控件；重复资源 ID 继续使用严格节点身份。密码保护和原文比对不变。

Android 无障碍在空字段时可能通过 getText 返回 hint。isShowingHintText 的内容统一视为空字符串，不能回填为正文。NONE/短暂失焦不退出同步循环，不关闭通道或清空手机草稿；已有绑定时仍可在手机编辑，焦点恢复后续传。若写入实际成功但读取回执前控件消失，会根据原待写值重新确认，避免把后续输入误判为冲突。

真正的编辑冲突暂停写入并保留会话，用户明确重新同步才继续；关闭、确认完成或真实传输错误才退出循环。回归测试覆盖候选窗口、错误窗口类型、占位提示、清空失焦/节点变化、清空后继续输入、空文本会话保持。

本次只读取了索尼电视输入法组件元数据；发现旧键盘会话仍在使用，未创建第二个自动化连接，以免打断用户。新版本的真实候选栏/清空交互仍需重新安装后验证。

## 审阅修复补充

手机草稿使用独立的本地编辑标志；清空尚未得到回执时，即使重新输入的文字恰好等于旧原文，也必须保留并在恢复后写回。测试覆盖清空 → NONE → 重新输入原文 → 恢复的完整过程。

保留旧编辑器仅限输入法正在接管焦点且没有其他控件获得输入焦点。焦点切到同页按钮或输入法已关闭时返回 NONE；会话保持等待。确定动作还必须重新刷新并验证节点仍有输入焦点，临时保留的失焦节点不得触发全局 Enter。主机 API 替身测试覆盖上述情况，真实电视与手机仍需复测。
